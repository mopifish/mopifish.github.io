Constrained Point

This method of procedural animation relies almost entirely on 2D Chain Simulations. One simple way to do a chain simulation is rooted in the idea of the constrained point.




Math Explanation

In the example above

  • The Anchor, Point A, is represented by the mouse cursor
  • The Constrained Point, Point P, is represented by the black dot
  • The Constraint Distance is represented by the circle.

In order to constrain our point to an anchor, we simply have to get the Vector between our two points, and set its length to equal the constraint distance. We then add our new vector to Point A to get our new, constrained, Point P

Note on Constraint: This particular point is constrained to be a fixed distance from the point at all times. This allows us to both push and pull on the point. You could also constrain the point in other ways, such as allowing it to be inside of the circle but not outside of it.


So Whats the Actual Math Behind This?

First we need to get the vector between the two points, which we can do by subtracting them from eachother. I'll represent this vector with the term ->AP.

Vector Formula
->AP = [P.x - A.x, P.y - A.y]
Why does this work?

A vector is a representation of movement from one point to another. Another way to describe would be the difference between two points. As a result, one point minus another will always equal a vector.

We can then use the Pythagorean Theorem to get the length of our vector.

Vector Length Formula
length = sqrt(->AP.x^2 + ->AP.y^2)
Why does this work?

When a vector is expressed in [X, Y] notation, it effectively functions as they hypotenuse of a right triangle. Since the pythagorean theorem allows us to get the length of one side of a triangle as long as we know the other two sides, this allows us to get the length of our vector.

After that we need to
Normalize

Normalization

Reducing a Vector's length to 1 so it can represent a Direction. Reducing a Vector to a scale of 1

->AP to convert it to a direction. I'll represent the normalized version of ->AP as ^AP.

Vector Normalization Formula
^AP = ->AP/length
Why does this work?

A vector is comprised of two things: a Direction and a Magnitude. When we reduce the vectors length to 1, we essentialy remove it's magnitude so it functions purely as a direction. In the above formula, we divide the vector by it's own length to reduce its magnitude to 1.

Now that we have the direction we can multiply it by our constraint distance to get our final vector, which I'll refer to as ->APf

->APf = ^AP * length

And then, as our final step, we add our new vector to Point A to generate our final, constrained, Point P, which I'll refer to as Point Pf.

Constrained Point
Point Pf = ->APf + Point A
Why does this work?

A vector is a representation of movement. We got the movement from Point A to Point P in the beginning, and then reduced the distance moved without changing the direction. If we then start at Point A and follow our new Vector, we'll arrive at where Point P would be if it was constrained to our circle.

If you would lke to see this executed practically, and in once concise step, view the code below

Code 
function constrain_point(point, anchor, distance) {
    var result = (point - anchor).normalize() * distance + anchor;

    return result; 
}
      
function get_vector_length(a, b) {
   /* Anchor and Point are both Paper.js Point classes, 
   and store an (X,Y) value. 
   It is equivalent to a Vector class */
   var vector = b - a;
   var length = Math.sqrt(vector.x*vector.x + vector.y*vector.y);

   return length; 
}

FABRIK Chain

To go from a snake to a lizard, we're gonna need some legs. This Inverse Kinematic chain will serve as the "bones" of our lizard legs.





Math Explanation

FABRIK, or Forwards and Backward Reaching Inverse Kinematics, is a technique where we constrain our chain to a target point (like in our earlier example) and then constrain it to it's anchor point by constraining every point to the point before it. This only gives us a close approximation of what the chain should look like though. We have to repeat this process several times to get a more accurate solution.

In the above example, I solve the chain using FABRIK continuously, or every frame, so we get a constantly accurate result. If you want to see what a single solution looks like, check the "Solve Manually" box and click your mouse to solve the chain one step at a time.


So Whats the Actual Math Behind This?

A Kinematic Chain is basically an assembly of objects connected by joints. Your arm is an example of a kinematic chain, where the objects are your bones and the joints are your shoulder/wrist/elbow. Our earlier constrained chain was also a kinematic chain. The dots represented our joints, and you can think of the circles as the "objects" linked together by these joints.

There are two types of Kinematic Chains. Forward Kinematic chains and Inverse Kinematic Chains.

A Forward Kinematic (FK) chain is a chain where you solve for the position of the objects based on the rotation of the joints. In simpler terms, its a chain where you individually move each joint in order to pose the arm. Thing of a small wooden mannequin, or an action figure.

An Inverse Kinematic (IK) chain is a chain where you solve for the rotation of the joints based on the position of the objects. This type of chain is much more useful in game development because it allows us to set a target position and the chain will automatically orient itself to reach that position. Think of your own arm when you're reaching for something as an IK chain.
